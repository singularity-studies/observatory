# Contributing

Contributions should improve the research infrastructure without asserting unsupported findings.

## Workflow

1. Open an issue or draft pull request describing the instrument or infrastructure change.
2. Keep scientific and software changes narrowly scoped.
3. Add or update tests for machine-enforced invariants.
4. Record scientific instrument version changes explicitly.
5. Run the validation commands in `README.md`.
6. Request review from the relevant governance role once roles are assigned.

## Evidence contributions

Do not submit fabricated, synthetic, or illustrative records into scientific data paths. Future real evidence must satisfy the versioned schema, retain its source locator and observation date, and distinguish source content from interpretation. Do not include private or sensitive personal data without prior authorization and governance review.

## Locked material

Never edit or delete a Wave that was locked on the base branch. Propose an append-only amendment or a later-Wave correction.

## Scientific changes

After Wave 0, changes to protocol, codebook, panel rules, schedule, governance, or schemas require a new instrument version and decision record. Explain comparability consequences in the pull request.
